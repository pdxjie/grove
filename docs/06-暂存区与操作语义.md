# 06 暂存区与操作语义（Staging Contract）

> 这份文档把"暂存 / 提交 / 遴选 / 贮藏"的语义写死。
> 目的：任何实现细节有争议时，以本文为准；UI 的每个动作都能对应一条明确的 git 命令。

---

## 1. 三棵树模型

Git 的一切"看起来奇怪"的行为，都来自三棵树不一致：

```
HEAD（最后一次提交）  ──┐
                        ├── 提交只读取 Index
Index（暂存区）        ──┤
                        ├── 暂存只写入 Index
工作区（磁盘文件）      ──┘── 编辑只改工作区
```

Grove 的界面必须**始终让人看见三者的差**，而不是把它们揉成一个"变更列表"。

| 位置 | 界面区域 | 颜色/标记 |
|------|----------|-----------|
| 工作区 ≠ Index | 未暂存（Unstaged） | 橙色圆点 |
| Index ≠ HEAD | 已暂存（Staged） | 绿色勾选 |
| 两边都有（部分暂存） | 同时出现在两个区 | 半环 ◐ |
| 冲突（Index 有 stage 1/2/3） | 冲突区 | 橙色警示 |

## 2. 文件状态矩阵

| porcelain | 含义 | 出现在 | 可用动作 |
|-----------|------|--------|----------|
| `??` | 未跟踪 | 未暂存 | 暂存（`git add`）、移到废纸篓、加入 `.gitignore` |
| ` M` | 已修改未暂存 | 未暂存 | 暂存、丢弃改动、查看 diff |
| `M ` | 已暂存修改 | 已暂存 | 取消暂存、查看已暂存 diff |
| `MM` | 部分暂存 | **两边** | 分别操作两侧 hunk |
| `A ` | 新增已暂存 | 已暂存 | 取消暂存（回到 `??`） |
| `AM` | 新增后又改 | 两边 | 分别操作 |
| ` D` / `D ` | 删除（未暂存 / 已暂存） | 对应区 | 暂存删除、恢复文件 |
| `R ` | 重命名（已暂存） | 已暂存 | 取消暂存 |
| `UU` `AA` `DU` `UD` | 冲突 | 冲突区 | **不可直接暂存**，必须先解决或"标记已解决" |

**规则**：冲突文件在解决前，暂存按钮置灰，悬停提示"先解决冲突"。

## 3. 快速暂存（Quick Stage）

"快速"的标准：**单文件 1 次点击 / 1 次按键，目录 1 次点击，全部 1 个快捷键。**

### 3.1 操作表

| 操作 | 鼠标 | 键盘 | 结果 |
|------|------|------|------|
| 暂存单个文件 | 点复选框 / 双击行尾 | `空格` | `git add -- <path>` |
| 取消暂存 | 再点一次 / 在已暂存区点 | `空格` | `git restore --staged -- <path>` |
| 暂存整个目录 | 点目录复选框（三态） | `⌥空格` | 递归暂存该目录下所有变更 |
| 全部暂存 | 顶部按钮 | `⇧⌘A` | `git add -A`（受本地私有规则过滤） |
| 全部取消 | 顶部按钮 | `⇧⌘U` | `git restore --staged .` |
| 反选 | — | `⌥⌘A` | 已选 ↔ 未选 |
| 拖拽到暂存区 | 拖文件到"已暂存"标题 | — | 同暂存 |
| 暂存当前 hunk | diff 内 hunk 头按钮 | `⇧空格` | `git apply --cached` |
| 暂存选中行 | 选中行后右键 | `⌥⇧空格` | 行级 patch |

### 3.2 目录树

- 文件列表默认**按目录树**展示，每个目录节点聚合子项状态：
  - 全选 = 实心勾；部分 = 半选（横线）；全不选 = 空。
- 目录节点显示聚合统计：`src/Service (3)`。
- 空目录不显示；单文件目录自动折叠（`a/b/c.php` 显示为一行 `a/b/c.php`）。

### 3.3 部分暂存的文件怎么显示

同一个文件同时出现在两个区，标题显示 `◐ 部分暂存`，点开后是**双栏对照**：

```
已暂存（将被提交）        未暂存（不会提交）
+ $channel = ...           - $channel = ...
```

- 未暂存侧可继续暂存 hunk；已暂存侧可取消暂存 hunk。
- 提交统计只算已暂存侧。

### 3.4 删除与重命名

- 工作区删除 → 显示为删除，暂存 = 记录删除（`git add -A -- path`）。
- 重命名：优先用 `git status` 的重命名检测（`-M`），显示 `old → new`；取消暂存后回退为"删除 + 未跟踪"两项。
- 丢弃未跟踪文件：**移到废纸篓**（可恢复），不执行 `git clean -fd`。

## 4. 提交边界：只提交暂存区

### 4.1 铁律

1. **提交内容 = Index**，任何情况下不隐式 `git add`。
2. 提交按钮上的数字/行数**只统计已暂存**。
3. 有未暂存改动时，提交面板显示提示条："另有 5 个文件未暂存，不会包含在本次提交"，并提供 [全部暂存] 快捷，但**不阻拦提交**。
4. 提交失败（pre-commit hook 拒绝、签名失败、空提交）→ 保留已输入的 message、保留暂存状态、展示 hook 输出原文 + 人话解释。
5. 冲突未解决时禁止提交（预检：`git diff --name-only --diff-filter=U`），提示还剩几个文件。

### 4.2 提交面板

```
┌──────────────────────────────────────────────┐
│ 提交到 main                                  │
│ ┌──────────────────────────────────────────┐ │
│ │ feat: 库存分配支持渠道维度                │ │
│ │                                          │ │
│ └──────────────────────────────────────────┘ │
│ ☐ 修改最后一次提交  ☐ 签名  ☐ 提交后推送      │
│ 已暂存 3 个文件 · +58 −12                     │
│ ⚠ 另有 5 个文件未暂存，不会提交    [全部暂存] │
│                           [提交]  ⌘↩         │
└──────────────────────────────────────────────┘
```

- 提交后清空 message，保留暂存区（Git 行为），并提示"已提交 abc1234 · 撤销"。
- 空 message：默认阻止；可在设置里允许（`--allow-empty-message` 需显式开启）。
- 修改最后一次提交（amend）：只允许在未推送时启用，已推送时给红色提示但不禁用（用户可能就是要 force push，但 Grove 不代劳）。

### 4.3 命令映射

```
暂存文件        git add -A -- <path>
取消暂存        git restore --staged -- <path>      # git ≥ 2.23
暂存 hunk       git apply --cached --unidiff-zero -   # 由 diff 生成的 patch
取消 hunk       git apply --cached -R
提交            git commit -F -                      # message 走 stdin，避免转义问题
修正提交        git commit --amend -F -
签名提交        git commit -S -F -
```

## 5. 遴选（Cherry-pick）

**定义**：把其他分支（或历史上）的若干个提交，逐个"摘"到当前分支。

### 5.1 入口

- 历史列表多选提交 → 右键"遴选到当前分支"；
- 提交详情页 → 右上角"遴选"；
- 分支列表 → 分支右键"遴选此分支的最新提交"；
- 命令面板：`Cherry-pick…`。

### 5.2 行为

- **顺序**：多选时按 `git rev-list --topo-order --reverse` 排序，不按点击顺序（避免依赖倒置）。
- **作者**：保留原作者（cherry-pick 的默认行为），committer 是当前用户；界面标注"原作者：张三"。
- **`-x` 选项**：默认关闭；开启后在 message 末尾追加 `(cherry picked from commit abc1234)`，便于追溯。
- **不提交模式**：高级选项"只应用到工作区"（`--no-commit`），用于"我只想要这个改动，自己整理后再提交"。
- **进度**：N 个提交显示 `遴选 2/5`，可暂停/中止。
- **冲突**：立即进入冲突中心（与 rebase 同一套界面与状态机），支持 继续 / 跳过该提交 / 中止并回滚。
- **撤销**：完成后写恢复点，⌘Z 回到 `ORIG_HEAD`，并提示"已撤销 3 个遴选提交"。

### 5.3 命令映射

```
单个/多个     git cherry-pick <sha1> <sha2> ...
带来源        git cherry-pick -x <sha>
不入库        git cherry-pick -n <sha>
继续          git cherry-pick --continue
跳过          git cherry-pick --skip
中止          git cherry-pick --abort
```

### 5.4 边界

- 合并提交默认不允许遴选（提示"请选择其父提交或先 rebase"），除非显式加 `-m`；
- 目标分支有未提交改动且会被覆盖时，先提示"先暂存/贮藏"，不自动 stash；
- 遴选进行中，禁止切分支/开始新的 rebase。

## 6. 贮藏（Stash）

### 6.1 创建

右键"贮藏…"打开小面板，选项互斥清晰：

| 选项 | 命令 | 说明 |
|------|------|------|
| 全部改动（默认） | `git stash push -m <msg>` | staged + unstaged，不含未跟踪 |
| 包含未跟踪文件 | `-u` | 新增文件也藏起来 |
| 包含被忽略文件 | `-a` | 慎用，面板标注 |
| 仅贮藏已暂存 | `--staged` | git ≥ 2.35；把暂存内容单独藏起来 |
| 贮藏但保留暂存区 | `--keep-index` | **最常用**：藏起未暂存部分，暂存区原样留着继续提交 |
| 仅贮藏选中文件 | `-- <paths>` | 从文件列表右键进入 |

**默认不勾选"包含未跟踪"**，与 git 一致；但面板上用一句话说明"新文件不会被贮藏"，避免踩坑。

### 6.2 列表与操作

- 列表项：message、来源分支、时间、文件数、`stash@{n}`；
- 选中即预览 diff（与普通 diff 同一渲染器）；
- 动作：应用（apply）、弹出（pop）、删除（drop）、从贮藏建分支、复制 sha；
- **pop 默认带 `--index`**，尽量恢复"哪些是已暂存"；恢复失败时提示但内容不丢。

### 6.3 冲突与撤销

- apply/pop 产生冲突 → 进入冲突中心；中止 = 恢复到 apply 前（用恢复点，不用 `checkout -- .` 这种粗暴命令）。
- drop 可撤销：journal 记录 stash 的 commit sha，撤销时 `git stash store -m <msg> <sha>` 放回列表。
- 贮藏不会被 gc 掉（有 reflog 引用），因此"误删可恢复"是可靠的。

### 6.4 命令映射

```
创建        git stash push -m <msg> [--keep-index] [--staged] [-u] [-- <paths>]
列表        git stash list --format=%gd%x1f%gs%x1f%ct
预览        git stash show -p --stat stash@{n}
应用        git stash apply --index stash@{n}
弹出        git stash pop --index stash@{n}
删除        git stash drop stash@{n}
恢复删除    git stash store -m <msg> <sha>
建分支      git stash branch <new-branch> stash@{n}
```

## 7. 与"本地私有文件"规则的交互

- 命中 local-only 规则的文件：在暂存区**灰显 + 默认不勾选**；
- "全部暂存"会跳过它们，并在提示条说明"已跳过 3 个本地私有文件"；
- "贮藏全部"同样跳过（避免把本地配置藏丢），可在面板里手动勾选"包含私有文件"；
- 提交前预检：若 Index 中仍含命中文件 → 阻止提交，列出文件，提供 [取消暂存这些文件]。

## 8. 快捷键总表（暂存相关）

| 快捷键 | 动作 |
|--------|------|
| `空格` | 暂存/取消暂存选中文件 |
| `⌥空格` | 暂存整个目录 |
| `⇧空格` | 暂存当前 hunk |
| `⌥⇧空格` | 暂存选中行 |
| `⇧⌘A` | 全部暂存 |
| `⇧⌘U` | 全部取消暂存 |

| `⌥⌘S` | 贮藏全部改动 |
| `⇧⌘S` | 打开贮藏面板（带选项） |
| `⌘Z` | 撤销上一步（含暂存/贮藏） |

## 9. 验收用例

1. 文件 A 改两处，只暂存第一处 → A 显示 ◐，提交只含第一处，工作区保留第二处。
2. 目录 `src/` 下 5 个改动，点目录复选框 → 5 个全部暂存；再点一次 → 全部取消。
3. 已暂存 2 个文件、未暂存 3 个 → 提交按钮显示"2 个文件"，提交后工作区仍有 3 个未暂存改动。
4. 未跟踪文件 `a.php` → 暂存 → 提交 → 存在；取消暂存 → 回到未跟踪（文件不丢）。
5. 冲突文件 → 暂存按钮置灰；解决后变可用。
6. 从 `feature/x` 遴选 3 个提交到 `main`，中间 1 个冲突 → 解决 → 继续 → 3 个都到齐；⌘Z 全部撤销。
7. 暂存一半改动 → "贮藏但保留暂存区" → 工作区干净、暂存区还在 → 提交 → pop 恢复未暂存部分。
8. 误删贮藏 → ⌘Z → 贮藏回到列表且内容完整。
9. 命中 `*_test.php` 的文件在执行"全部暂存"时被跳过，并有提示。
10. pre-commit hook 失败 → message 保留、暂存区保留、展示 hook 输出。

## 10. 版本要求

| 能力 | 最低 git |
|------|----------|
| `git restore` | 2.23 |
| `stash push --staged` | 2.35 |
| `stash push --keep-index -u` | 2.13 |
| `status --porcelain=v2` | 2.11 |
| `switch` / `restore` 全套 | 2.23 |

本机 git 2.39.5 满足全部要求。低于 2.23 时降级到 `reset HEAD --` 并提示升级。
